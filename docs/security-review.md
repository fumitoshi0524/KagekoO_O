# Pre-release security review (0.x)

Scope: built-in URL fetching, workspace path resolution, shell permission decisions, project extensions and generated capabilities, and local credential and log handling. Read the [security boundaries](security-boundaries.md) for the user-facing contract. These findings describe the current implementation and regression tests; they do not certify Kageko as a sandbox.

| Area | Reviewed and tested | Remaining boundary |
| --- | --- | --- |
| Network | `fetch_url` checks the destination before connecting, rechecks redirects, and connects to a checked resolved address. Regression tests cover private and special-use IPv4/IPv6 literals and a public-to-local redirect. Opening `/setup` without a provider no longer starts the default OAuth network flow. | Shell commands, MCP servers, hooks, plugins, and custom model endpoints retain the current user's network access. URL filtering applies only to the built-in fetch tool. DNS and proxy behavior should also be checked in the deployment environment. |
| Paths | File tools check lexical traversal and symlink targets against the workspace. Tests cover `..` traversal and a directory link crossing the boundary (a junction on Windows). | A hostile local process may race path checks against later file operations. Workspace checks are not isolation from other processes on the machine. |
| Shell and permissions | Tests verify that credential paths are not silently approved, unattended mode denies unresolved approvals, `unrestricted` still blocks hard-denied commands and writes to learner-managed paths, and a session approval applies only to the matching shell command. A regression test confirms common credential variables and Node injection settings are removed from child environments by default. | Command classification covers recognized patterns. An approved shell command retains the user's filesystem and network permissions. Secrets in unusually named variables or files may remain accessible. |
| Extensions | Project configuration has a workspace trust gate; a regression test confirms that modified extension code invalidates a prior trust grant. Generated tools, MCP servers, and skills have proposal review, loading, and fresh-process acceptance paths. | Trusted or approved extension code can still access external systems. Review does not prove third-party code is harmless. |
| Credentials and logs | Unix credential stores enforce private directories and files; tests cover private and public parent directories. Telemetry is off by default and has a redaction regression test when enabled. | Credentials are not encrypted at rest; Windows protection depends on actual ACLs. Sessions, tool output, and diagnostics may contain sensitive content. Heuristic redaction is incomplete by design. |

Release posture: document Kageko 0.x for **trusted local workspaces with human review of approvals**. Do not claim safe execution of arbitrary untrusted repositories, shell commands, or extensions. The three-platform CI suite and isolated package installation check remain release gates alongside this review.
