# 发布前安全专项审查（0.x）

审查范围：内置 URL 获取、工作区路径解析、Shell 权限判断、项目扩展与生成能力，以及凭据和日志的本地处理。运行边界见[安全边界说明](security-boundaries.zh-CN.md)。以下结论只适用于当前源码和自动化测试，不构成沙箱或全面安全认证。

| 领域 | 已核查与验证 | 仍需明确的边界 |
| --- | --- | --- |
| 网络 | `fetch_url` 在连接前检查地址，在每次重定向后重新检查，并将实际连接绑定到已检查的解析结果。新增私网、特殊用途 IPv4/IPv6 和公网转本地重定向回归测试。修复无参数打开 `/setup` 时误触发默认 OAuth 网络请求的问题。 | Shell、MCP、hook、plugin 和自定义模型 endpoint 可按当前用户权限访问网络；URL 过滤只约束内置获取工具。DNS 与代理行为仍应在目标部署环境复测。 |
| 路径 | 文件工具对词法越界和符号链接目标做工作区检查；新增 `..` 越界及目录链接跨界测试（Windows 使用 junction）。 | 路径检查与后续文件操作之间存在文件系统竞态的可能；不能把工作区检查视作对恶意同机进程的隔离。 |
| Shell 与权限 | 测试了敏感凭据路径不会自动获准、无人值守模式拒绝待批准操作、`unrestricted` 仍拒绝硬性禁止命令及学习器管理目录写入，以及会话授权只复用于匹配的 Shell 命令。回归测试确认子进程默认移除常见凭据环境变量和 Node 注入配置。 | 命令分类只能处理已识别的模式；获准执行的 Shell 仍拥有当前用户的文件和网络权限。自定义名称的秘密变量和文件中秘密不保证被清除。 |
| 扩展能力 | 项目配置有工作区信任门槛；回归测试确认扩展代码变化后原信任授权失效。生成的工具、MCP 和 skill 有提案审核、加载及跨进程验收路径。 | 经用户信任或批准的代码和命令仍可访问外部系统。审核流程不能证明第三方扩展无害。 |
| 凭据与日志 | 凭据存储对 Unix 私有目录和文件权限做检查，新增私有目录及公开目录测试；遥测默认关闭，启用后有脱敏回归测试。 | 凭据没有静态加密；Windows 依赖实际 ACL。会话、工具输出与本地诊断可能含敏感内容；启发式脱敏不保证覆盖所有秘密。 |

发布结论：可以作为面向**受信任本地工作区、有人审查授权**的 0.x 版本说明安全边界。不要宣称能够安全执行任意不可信仓库、Shell 命令或扩展。发布包仍须通过 CI 的三平台测试和隔离安装验证；这些检查与本专项审查共同作为发布门槛。
