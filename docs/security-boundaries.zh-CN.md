# 安全边界（0.x）

Kageko 以当前用户的操作系统权限在本机运行。权限配置决定工具调用何时需要批准，**不等于操作系统沙箱**。请只在你愿意信任的工作区中运行，并审查启用的扩展。

## 工具权限

- 默认配置是 `--permission manual --interaction interactive`。内置的本地读取和公开网页读取可能自动获准；其他操作通常需要批准。明确的拒绝规则和强制禁止规则优先。
- `workspace` 还会批准工作区内的写入和部分可分类的 Shell 操作。`unrestricted` 会批准剩余操作，但仍受强制禁止规则和明确要求询问的规则约束。两者都不会把 Shell 进程限制在工作区内。
- `unattended` 无法向用户询问；仍需批准的操作会被拒绝。不应仅为让无人值守任务通过而启用 `unrestricted`。
- 文件工具会按工作区解析路径并检查符号链接目标。Shell 命令作为普通子进程运行，可以使用当前用户拥有的文件和网络权限。命令分类及环境变量清理只能降低风险，不能让任意 Shell 代码变安全。

## 凭据、会话和日志

- 模型凭据和 MCP 令牌分别保存在本地 `~/.kageko/auth.json` 和 `~/.kageko/mcp-tokens.json`，**没有静态加密**。Unix 上要求存储目录为私有目录并写入私有文件；Windows 上的实际访问控制取决于账户和文件系统 ACL。
- Kageko 默认从子进程环境中移除常见名称的凭据变量。名称特殊的秘密变量或文件中的秘密仍可能被 Shell 命令或扩展访问。
- 会话、工具输出、记忆和学习产物会留在本地，可能包含代码或敏感内容。分享诊断文件前应先检查。
- 遥测默认关闭；启用后在本地限量、限期保存，并采用启发式脱敏，不会自动上传。脱敏无法保证识别所有秘密。

## 网络和扩展

- 内置 URL 获取工具只允许 HTTP(S) 公网目标，并检查解析后的地址与重定向。网页搜索会把查询发送给 DuckDuckGo Lite。模型服务商会收到会话所需的提示词和工具结果，请检查所选服务商与 endpoint。
- 项目 MCP server、hook、plugin、skill 和生成的能力可能执行代码或访问外部服务。Kageko 在加载安全敏感的项目配置前要求工作区信任，生成能力也有审核流程；启用前仍应审查来源和内容。
- 权限检查和网络过滤属于纵深防护。对不可信的多租户环境，应另外使用操作系统或容器级隔离。
